Comprendre les technologies RAID

Brouillon pédagogique fondé sur le document d'origine « Architecture RAID : différences des configurations 0, 1, 5, 10, 01 ».

1. Comprendre la technologie RAID

RAID signifie Redundant Array of Independent Disks, ou regroupement redondant de disques indépendants.

Son principe consiste à répartir les données sur plusieurs disques. Selon la configuration retenue, l’objectif peut être d’améliorer les performances, la tolérance aux pannes ou de rechercher un compromis entre les deux.

Le choix dépend notamment des priorités et du budget de l’entreprise.

À retenir : la tolérance aux pannes offerte par certains RAID ne remplace pas une sauvegarde indépendante.
2. RAID 0 : privilégier les performances

Le RAID 0 répartit les données entre plusieurs disques. Dans l’exemple à deux disques du document original, une partie des données est écrite sur chacun.

  • Capacité utile : la capacité totale des disques, dans le cas de disques de même taille.
  • Objectif : améliorer les performances grâce au travail simultané des disques.
  • Tolérance aux pannes : aucune. La défaillance d’un disque compromet l’ensemble du volume.
Exemple : deux disques de 200 Go forment un volume RAID 0 de 400 Go utiles.
3. RAID 1 : dupliquer les données

Le RAID 1 utilise la mise en miroir : les mêmes données sont enregistrées sur deux disques dans l’exemple étudié.

  • Capacité utile : la moitié de la capacité totale pour deux disques identiques.
  • Objectif : conserver l’accès aux données si l’un des deux disques tombe en panne.
  • Limite : le miroir ne protège pas contre une suppression accidentelle ou une corruption répliquée.
Exemple : deux disques de 200 Go offrent 200 Go utiles en RAID 1.
4. RAID 10 et RAID 01 : combiner miroir et répartition

Ces deux architectures utilisent au moins quatre disques et associent les principes de RAID 0 et RAID 1.

5. RAID 5 : répartir la parité

Le RAID 5 répartit les données et les informations de parité sur au moins trois disques. La parité permet de reconstruire les données après la panne d’un disque.

  • Nombre minimal : trois disques.
  • Capacité utile : (nombre de disques - 1) × capacité du plus petit disque, lorsque les disques sont de capacité identique pour cet exemple.
  • Tolérance aux pannes : un disque.
Exemple du document : 3 disques de 200 Go donnent (3 - 1) × 200 = 400 Go utiles.
6. RAID 6 : deux informations de parité

Le RAID 6 reprend le principe de répartition des données, avec une capacité équivalente à deux disques réservée à la parité.

  • Nombre minimal : quatre disques.
  • Capacité utile : (nombre de disques - 2) × capacité d’un disque, dans un ensemble homogène.
  • Tolérance aux pannes : jusqu’à deux disques.
Exemple du document : 4 disques de 200 Go donnent (4 - 2) × 200 = 400 Go utiles.
À vérifier dans la version définitive : le document d’origine indique une seule panne tolérée pour RAID 6. Cette formulation doit être corrigée lors de la révision du cours.
