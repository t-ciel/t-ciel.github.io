DNS

1. À quoi sert le DNS ?

Le DNS (Domain Name System) permet à un ordinateur de trouver l'adresse IP associée à un nom.

Grâce au DNS, nous utilisons des noms faciles à retenir plutôt que des adresses IP.

Exemple sur Internet :

Le serveur DNS associe le nom www.arte.net à l'adresse IPv4 192.0.2.10.

Exemple dans une entreprise :

Le serveur DNS peut associer le nom srv-fichiers.entreprise.local à l'adresse IPv4 192.168.1.10.

Quand ton ordinateur veut contacter un serveur, il peut demander son adresse IP au serveur DNS.

Le serveur DNS lui répond. Ton ordinateur peut alors contacter le serveur recherché.

3. Structure d'un nom de domaine

Un nom DNS contient plusieurs parties séparées par des points.

Dans nos exemples :

hôte.sous-domaine.domaine.extension

Un nom DNS ne comporte pas toujours de sous-domaine.

Exemple sur Internet (serveur de messagerie) :

mail.paris.arte.net

Exemple sur Internet (serveur web) :

www.paris.arte.net

Exemple dans le réseau interne d’une entreprise (serveur de fichiers) :

srv-fichiers.rennes.cybernet.fr

4. Les enregistrements DNS

Un enregistrement DNS contient un nom, un type et une valeur.

1. Enregistrement A (IPv4)

Il associe un nom DNS à une adresse IPv4.

Internet : mail.paris.arte.net → 203.0.113.10

Réseau local : srv-fichiers.rennes.cybernet.fr → 192.168.1.10

2. Enregistrement AAAA (IPv6)

Il associe un nom DNS à une adresse IPv6.

Internet : mail.paris.arte.net → 2001:db8:1::10

Réseau local : srv-fichiers.rennes.cybernet.fr → fd12:3456:789a::10

À retenir : un même nom DNS peut posséder un enregistrement A et un enregistrement AAAA.

Extrait du fichier de zone arte.net
; Nom DNS complet                      Classe Type  Valeur
mail.paris.arte.net.                 IN     A     203.0.113.10
mail.paris.arte.net.                 IN     AAAA  2001:db8:1::10

3. Enregistrement CNAME

Il permet d'utiliser un alias (un « surnom ») qui renvoie vers un nom DNS existant.

Seul l’hôte change :
partage.rennes.cybernet.fr → srv-fichiers.rennes.cybernet.fr

Deux noms complètement différents :
boutique.arte.net → serveur1.hebergement.fr

Extraits de fichiers de zones DNS
; Zone cybernet.fr
partage.rennes.cybernet.fr.  IN  CNAME  srv-fichiers.rennes.cybernet.fr.
; Zone arte.net
boutique.arte.net.       IN  CNAME  serveur1.hebergement.fr.

4. Enregistrement MX

Il indique le serveur chargé de recevoir les courriels d'un domaine.

Internet : arte.net → mail.arte.net

Entreprise : cybernet.fr → mail.cybernet.fr

Extraits simplifiés de fichiers de zones DNS
; Zone arte.net
arte.net.  IN  MX  10 mail.arte.net.
; Zone cybernet.fr
cybernet.fr.  IN  MX  10 mail.cybernet.fr.

6. Enregistrements TXT et sécurité des courriels


Le DNS ne sert pas seulement à retrouver des adresses IP. Il peut aussi publier des informations sous forme de texte.




📝
TXT : publier du texte dans le DNS
Un enregistrement TXT contient un texte associé à un nom de domaine. Ce texte peut servir à vérifier un domaine ou à donner des consignes aux serveurs.
À quoi ça ressemble ? Voici un enregistrement TXT. Le texte entre guillemets est une information que les serveurs peuvent lire.
arte.net.  IN TXT "verification=exemple123"
Ceci est un exemple fictif de texte. TXT n’est pas une protection à lui seul.


📤
SPF : qui a le droit d'envoyer ?
Le propriétaire d'un domaine indique dans le DNS quels serveurs sont autorisés à envoyer des courriels pour son domaine.
À quoi ça ressemble ? Cette règle SPF autorise le serveur 192.0.2.20 à envoyer des courriels pour arte.net.
arte.net.  IN TXT "v=spf1 ip4:192.0.2.20 -all"
-all indique que les autres serveurs ne sont pas autorisés.


🔏
DKIM : le courriel est-il bien signé ?
Le serveur d'envoi ajoute une signature numérique au courriel. Le serveur de réception utilise une clé publiée dans le DNS pour vérifier cette signature.
À quoi ça ressemble ? Une signature DKIM contient une longue suite de caractères. Le courriel transporte la signature et le DNS publie la clé publique utilisée pour la vérifier.
mail._domainkey.arte.net.  IN TXT
"v=DKIM1; k=rsa; p=MIIBIjANBgkqh... "
La clé est volontairement raccourcie ici : une vraie clé est beaucoup plus longue. Ce texte DNS est une clé publique, pas la signature du courriel.


🛡️
DMARC : que faire d'un courriel suspect ?
Le domaine publie une règle qui peut demander de laisser passer, de placer en courrier indésirable ou de refuser un courriel suspect. DMARC utilise les résultats de SPF et DKIM. Il vérifie aussi que le domaine de l'expéditeur affiché dans le courriel correspond au domaine utilisé par au moins un de ces contrôles.
À quoi ça ressemble ? Cette règle demande au serveur destinataire de refuser les courriels qui échouent au contrôle DMARC.
_dmarc.arte.net.  IN TXT
"v=DMARC1; p=reject"
p=reject signifie « refuser ». Le serveur destinataire applique sa propre politique de traitement.




À retenir : TXT est un type d'enregistrement DNS. SPF, DKIM et DMARC utilisent des informations publiées dans le DNS, souvent dans des enregistrements TXT. Ils aident à vérifier les courriels, mais ne garantissent pas qu'un message est sans danger.

7. DNS et cybersécurité


Des pirates peuvent utiliser le DNS pour voler des données, envoyer les utilisateurs vers de faux sites ou bloquer des services.




🛡️
DNS spoofing (fausse réponse DNS)
Le pirate envoie une fausse adresse IP à un ordinateur.
Exemple : tu veux aller sur le site de ta banque, mais tu arrives sur un faux site qui lui ressemble.


🗃️
DNS cache poisoning (fausse réponse enregistrée)
Le pirate fait enregistrer une fausse adresse IP dans la mémoire d'un serveur DNS.
Exemple : plusieurs clients d'un magasin en ligne sont envoyés vers le même faux site.


🌐
DNS hijacking (détournement du serveur DNS)
Le pirate change les réglages DNS d'un ordinateur ou d'une box. Les demandes DNS passent alors par un serveur qu'il contrôle.
Exemple : ton ordinateur utilise un serveur DNS pirate à la place du serveur habituel.


⚡
Attaque DDoS contre le DNS (surcharge)
De nombreux appareils envoient simultanément un très grand nombre de requêtes DNS. Le serveur peut être saturé et ne plus répondre aux utilisateurs.
Exemple : des clients n'arrivent plus à ouvrir leur site de jeux préféré, car le serveur DNS ne répond plus.


📤
DNS tunneling (transport caché de données)
Un logiciel malveillant cache des données dans des demandes DNS pour les envoyer vers un serveur extérieur.
Exemple : un ordinateur infecté envoie discrètement des informations de l'entreprise dans ses requêtes DNS.

8. Reverse DNS et PTR


Le DNS classique permet de trouver une adresse IP à partir d'un nom. Le Reverse DNS fait l'inverse : il permet de rechercher un nom à partir d'une adresse IP.




DNS classique
Je connais le nom.
serveur.arte.net
↓
192.0.2.10
Enregistrement A


Reverse DNS
Je connais l'adresse IP.
192.0.2.10
↓
serveur.arte.net
Enregistrement PTR




Quelle différence ? Le Reverse DNS est une recherche. Le PTR est l'enregistrement DNS qui donne le nom trouvé.


À quoi sert le Reverse DNS ?


Un technicien consulte les journaux d'un pare-feu. Il remarque des connexions venant de l'adresse IP 192.0.2.10, mais ne sait pas quelle machine utilise cette adresse.


Il lance une recherche DNS inverse. Le DNS lui répond serveur.arte.net. Ce nom lui donne une piste pour identifier la machine et poursuivre son dépannage.


Le PTR peut être absent ou incorrect. Le nom obtenu est une indication, pas une preuve de l'identité du serveur.


Comment fonctionne la recherche inverse ?


Adresse IP de départ192.0.2.10
↓
Nom demandé au DNS10.2.0.192.in-addr.arpa
↓
Nom renvoyé par le PTRserveur.arte.net


En IPv4, les quatre nombres de l'adresse sont placés dans l'ordre inverse. On ajoute ensuite in-addr.arpa : c'est le domaine spécial utilisé pour le DNS inverse IPv4.


Voici à quoi ressemble un enregistrement dans une zone DNS inverse :


10.2.0.192.in-addr.arpa. IN PTR serveur.arte.net.


À gauche, on trouve le nom demandé. PTR est le type d'enregistrement. À droite, on trouve le nom de la machine renvoyé par le DNS.
